Phase 2's Prayer #2 reset is brittle. A 3-day streak that hard-resets after 24 hours will frustrate real-world users — kids get sick, people travel, life happens. Consider a 36–48 hour window, or a "I prayed yesterday" make-up tap available once per streak. Small change, real difference in completion rates. This matches what I wrote in the prompt, but on reflection my spec was too harsh.
Phase 1 needs the section-summary query to be aggregated. getWorkbookSummary(userId) will be called every time the user opens the Workbook. Make sure it's a single SELECT sectionId, COUNT(*) FROM workbook_entries WHERE userId = ? GROUP BY sectionId, not 18 separate queries. Worth pinning in the ticket — N+1 issues here are exactly the kind of thing an agent quietly introduces.
prayer-templates.ts will be the heaviest content file in the build, and Phase 3's "TODO: PASTORAL CONTENT NEEDED" placeholders are a trap. If you let the agent start Phase 3 with placeholders, it will invent prose to fill the gaps — and once it ships you'll spend weeks finding and replacing AI-generated prayer text. Prepare the full Prayer #1, #2, #3 source-manual text as a structured JSON file before Phase 3 begins, and hand the agent both the ticket and the JSON. The agent's job is rendering, not authoring; remove its excuse to author.
Phase 2's deep-link route is good — /resources/tools/freedom-workbook/:sectionId wasn't in my prompt explicitly, and it's the right addition for workbook_link slides to land on the correct section.
One small concern about attestation. Phase 1 mentions checkmarks for "sections that use attestation (sections that only have a checklist)" — so only Section 16. The other 17 stay as "empty" or "N entries" forever. That's fine for a resource, but worth knowing: a user who genuinely has nothing to add to Sections 3, 9, and 13 will see those sit at "empty" indefinitely. If that bothers you, add a per-section "I've considered this and have nothing to add" toggle. If it doesn't bother you, leave it.
