I have a swipeable card game using a JSON deck format. Each card has prompt, leftLabel, rightLabel, and optional effects, path, setPathOnChoice, end, and endText fields. Cards are shown top to bottom; a card with a path field only shows if the player is currently stamped with that path.
I need you to add three features on top of the existing engine without breaking any of the existing fields.
Feature 1: Three visible stat meters at the top of the screen
The game tracks three stats: worth, safety, and belonging. Each starts at 50 and is clamped between 0 and 100. Any card's effects object can modify these with positive or negative integers. Render three horizontal meter bars at the top of the screen — one per stat — with a small label and icon next to each. Amber/gold fill when the stat is in a healthy middle range (20–80), red fill when it is below 20 or above 80. The meters should animate when a choice changes them.
Feature 2: Wound tracking (effects keys that start with "R")
Any effects key that starts with a capital R followed by a number (e.g. R1, R2, R5, R6, R9, R10) is a wound flag, not a stat. Do not display these in the meter bar. Instead, track them silently. When a card's effects install a wound the player didn't previously have (i.e. the flag goes from 0 to 1), show a small subtle notification in the corner of the screen for 3 seconds that says WOUND INSTALLED — nothing else. The wounds are revealed narratively inside the prompts themselves.
Also keep an internal list of wound IDs the player has accumulated, in installation order. You will need this for Feature 3.
