Build a new slide type: Guided Prayer Process
I need a new slide type for my Catholic deliverance prep program. It walks users through multi-step prayer processes where their text inputs from earlier steps get woven into the prayers in later steps.
Why I need this
Existing slide types (text, text_input, single_select) can collect inputs and show text, but they can't insert user inputs into prayer text on later slides. That live insertion is the whole point — the user writes "I am unforgivable" in step 3, then in step 4 sees the prayer "In the name of Jesus Christ, I renounce the lie that I am unforgivable..." with their own words inside the prayer.
This is similar to the existing Breaking Lies slide type, but generalized. Keep Breaking Lies separate — don't refactor it. Build this as a new type called guided_prayer_process.
How it works
The slide is configured with an ordered array of steps. The component walks the user through them one at a time. User cannot skip ahead. User can go back to revise an earlier input; downstream prayers update with the new value.
Step kinds
The component must support these five step kinds:
1. instruction — Display-only text. Has a heading and body. User clicks "Continue."
2. input — Single text input. Has a heading, prompt, placeholder, and variable_name. User types, clicks "Continue." Continue is disabled until there's text.
3. list_input — Captures a list of items. Heading, prompt, variable_name, add_button_label, optional placeholder, optional optional: true flag. UX: one text field with an "Add another" button below it. Each added item appears as an editable, deletable row above the input. Continue is enabled once at least one item is added (or always enabled if optional: true). No limit on number of items.
4. choice — Single-select with branching. Heading, prompt, variable_name, and an options array. Each option has a label and a next_step (the step id to jump to). Used for things like "Was another person involved? Yes / No / Not sure" where Yes routes one way and No skips ahead.
5. prayer — Displays a prayer for the user to pray out loud. Has a heading, optional instruction_above, and prayer_text. The prayer_text supports inline variable insertion with {{variable_name}} syntax. User must click "I prayed this" to continue — no auto-advance, no skip button. Supports an optional show_only_if field (e.g. "inner_vows.length > 0") so prayers tied to optional inputs only appear if the user has data for them.
6. reflection — Like input, but a longer textarea framed as post-prayer journaling. Heading, prompt, variable_name, optional placeholder.
Variable insertion in prayers
This is the most important part to get right. When a prayer contains {{variable_name}}, the user's input is rendered inline. Rules:

Single text input → just insert the text.
List with 1 item → insert as plain text.
List with 2 items → "X and Y"
List with 3 items → "X, Y, and Z"
List with 4 or more items → render as a block. Break the prayer text at the variable, render each item as its own indented line (no bullets, just indented and italicized), then continue the prayer below. Like this:


Jesus, I have done
the affair
lying to my family for years
the night with my brother
missing my father's funeral
I ask you now to forgive me for what I did and for everything that came from it.

The user's inserted words should be visually distinct in all three formats — slightly different weight, color, or italicized — so the user can see their own words inside the prayer.
Other behaviors

Progress indicator at the top: "Step 4 of 15."
Going back to a previous step preserves the user's input; revising the input updates any downstream prayers using that variable.
All variables are saved to the user's record per slide completion, keyed by variable_name, stored as a JSON blob. Mentors will pull these up later — schema should make that easy.
On the final step (or after the last step), show a summary of everything the user wrote, so they can see what they walked through.
Prayer steps must require an explicit "I prayed this" click. No auto-advance. No skip.

Visual design

Instruction steps: standard body text, matches existing text slides.
Input / list_input / reflection steps: prompt above, input below, Continue button.
Prayer steps: visually distinct — soft background tint, indented block, serif or italic font, small "Pray out loud" label or icon at the top. The "I prayed this" button is styled as the primary action and is the only way to advance.
Choice steps: clear button group or radio options.

Requirements summary

New slide type: guided_prayer_process
Keep existing breaking_lies slide type untouched
Six step kinds: instruction, input, list_input, choice, prayer, reflection
Variable insertion in prayers with three rendering modes based on list length
Prayer steps require explicit "I prayed this" click, no skip
Branching via next_step on choice options
Conditional display via show_only_if
optional: true flag on list_input to allow zero items
All inputs saved per slide completion as JSON keyed by variable_name
Progress indicator
Summary at the end
Visual distinction between instruction text and prayer text

Build the component, wire it into the slide rendering system, and use the Forgiving Yourself config above as the test case.
